## 1. 目的、范围与状态用语

### 1.1 最终想交付什么

目标是建立一个新的、可复用的 **通信受限未知环境多机器人探索 benchmark**，而不只是把 IR2 换成 JAX，也不只是训练一个 PPO 模型。

期望交付包括：

1. 保留 IR2 核心探索语义的 JAX 环境，以及明确记录的 benchmark 扩展。
2. 可审计的通信协议、字节预算、物理信号与独立链路故障条件。
3. 固定地图划分、场景清单、统一指标、基线和可复现评测入口。
4. A：利用真实环境轨迹训练探索策略的路线。
5. B：学习环境动态模型，再利用想象轨迹训练策略的路线。
6. 队友意图估计、学习通信等可选方法组件及其对照。
7. 性能测量、训练曲线、探索录像、检查点与配置身份记录。

核心科学问题应是：在同一任务与真实通信成本下，哪些共享信息和决策机制能够提高探索效率、减少无效重叠，并在丢包或断联后维持性能？世界模型是否能进一步提高真实交互样本效率？

**不以“通信是否在任何情况下有用”作为主要创新点。** 需要证明的是特定方法在明确约束下的收益，并与已有有效通信基线比较。

## 2. 术语及 A/B 路线的准确含义

| 术语 | 本项目含义 |
|---|---|
| IR2 | 当前本地原版多机器人探索实现，作为感知、图维护、图观测和策略结构的对照 |
| 单机器人事件／真实动作 | 轮到一台机器人做一次决策并推进真实仿真；不是一次全队同步行动 |
| 全队轮次 | 按固定编号让各机器人依次行动一轮；4 台机器人通常对应 4 个事件 |
| 真实环境 | 相对于学习到的世界模型，指实际 JAX 仿真环境；不表示物理机器人实验 |
| Actor | 决定下一跳探索动作，以及可选通信动作的策略网络 |
| Critic | 训练时估计团队回报的价值网络，可使用明确分离的集中信息 |
| PPO | A 当前采用的策略优化算法；并非原版 IR2 的 SAC |
| ZOH | Zero-Order Hold，保留最后收到的计划值和原时间戳，不预测新计划 |
| 队友计划预测器 | 接收者侧估计队友当前意图的模型，不是完整环境动态模型 |
| 世界模型 | 预测动作导致的感知、位置、通信、奖励等变化，用于生成想象训练轨迹 |
| RSSM | Recurrent State-Space Model，包含确定性循环记忆和随机隐变量的状态模型 |
| 物理覆盖 | 所有机器人亲自感知区域的并集；不是所有机器人都已获得该信息 |
| 图融合 | 基于实际收到的地图信息扩展接收者的知识与图，不是免费访问队友内部图 |

### 2.1 A：真实轨迹训练

流程为：真实 JAX 环境采集 → 计算优势与回报 → PPO 更新 Actor/Critic → 可选更新队友计划预测器 → 下一批真实采集。

固定通信或学习通信、ZOH 或学习式预测，是 A 内部可以选择的维度。**A 并不天然要求启用计划预测器。** 最近实际运行的是固定 PLAN 通信＋ZOH，计划预测器没有训练。

### 2.2 B：世界模型想象训练

流程为：真实采集进入回放 → 训练环境世界模型 → 从真实历史状态推断想象起点 → 在学习模型中生成后续多机器人交互 → 用想象回报更新 Actor/Critic → 回到真实环境评估。

B 的环境世界模型与队友计划预测器是两个模块：

- 世界模型服务于训练数据生成，预测环境动态。
- 队友计划预测器服务于接收者的局部决策，估计失联队友的意图。
- B 可以采用 ZOH，仍然是 B；A 也可以采用计划预测器，仍然是 A。
- 当前 B 不是“执行时调用世界模型做在线搜索”的已实现承诺。
- 算法参考是 Dreamer 风格 RSSM／想象 Actor-Critic，但代码是项目适配实现，不能宣称完整复现官方 DreamerV3。

## 4. 当前环境：已实现的任务与接口

### 4.1 状态与决策建模

这是部分可观测多机器人决策问题。全局状态包含真值占据栅格、机器人位置、各自本地三态地图、图记忆、余额、收件箱、消息缓存、物理覆盖与事件时钟。分散策略只能获取本地观测和自己的记忆。

可以将其表述为带固定行动者顺序的合作式部分可观测决策过程：

- 全局状态 `s_e` 在单机器人事件 `e` 上推进。
- 当前行动者 `i` 读取 `o_i = observe(s_e, i)`。
- 动作包括一跳目标、发送开关、消息类型／载荷，以及自定义方法可使用的接收者选择。
- 环境转移返回新状态、团队奖励、成功／超时标记和诊断信息。
- 单独的局部观测一般不是马尔可夫状态；本地地图、图历史、通信缓存和策略记忆用于保留历史信息。
- `vmap` 批处理独立环境；同一个环境内固定顺序的机器人事件不能无条件改成同步执行。

主要接口为 `reset`、`observe`、`step_agent`，具体返回结构以源码为准。所谓“无状态函数”是没有隐藏可变状态，不是环境不保存状态。

### 4.2 地图、出生、感知、运动和结束

| 项目 | 当前实现／约定 | 边界 |
|---|---|---|
| 地图 | 原尺寸二值占据地图；局部未知／自由／占据三态 | 填充到计算桶不等于缩放地图 |
| 出生 | 在出生锚点对应自由连通分量内，按种子选择附近不同位置 | 属于 benchmark 规则，不能默认等同原版所有出生细节 |
| 计分区域 | 出生锚点所在的四邻接自由连通区域 | 与整张地图全部自由格仅在自由空间全连通时相同 |
| 感知 | `ir2_graph` 模式调用 IR2 射线语义的 JAX 传感器 | 已做针对性对照，不采用早期简化圆形视野作为正式描述 |
| 动作 | 从当前图邻接候选中选点，一次完成整条合法边 | 当前模式不按旧 `max_distance=20` 截断移动 |
| 距离 | 累计欧氏边长 | 不等于单像素步数 |
| 执行顺序 | 每轮按固定机器人编号依次行动 | 后行动者可获得本轮先行动者送达的信息，存在顺序影响 |
| 完成 | 团队亲自感知区域并集达到计分区域的 99% | 不要求信息已传播给所有机器人 |
| 超时 | 默认 512 全队轮次 | 成功与时间截断分开记录 |
| 碰撞假设 | 地图障碍限制运动，不模拟机器人实体间碰撞 | 不能把该基准结果直接当成真实避碰验证 |

当前导航模式还保留历史 `grid_path` 和简化 `ir2_one_hop` 供显式选择。**当前严格图模式是 `ir2_graph`，不能将旧模式的速度与学习结果混为一谈。**

### 4.3 IR2 一致性：已经做了什么，不能声称什么

已实现并记录针对性对照的部分包括：

- 原版传感器射线与边界行为；原版 `ndarray.itemset` 已改为兼容 NumPy 2 的赋值写法。
- 均匀图节点、历史节点、局部／全局边、分支扩展、图合并和前沿效用。
- 六维节点观测：坐标 x/y、探索效用、会合效用、guidepost、occupied。
- 图邻接、当前节点、节点与动作掩码。
- 接收者知识约束下的会合效用计算。
- 原版图注意力策略的同权重数值对照。

本项目**不是全部环境机制与原版完全相同**：付费消息、预算、故障、出生／计分区域、可选奖励和信号预设均为显式扩展。相同本地知识下的图／观测对齐，不等于相同全局通信过程。

队友图融合开关关闭时，自身历史仍保留；开启后也只能使用成功收到的 MAP_DELTA 等合法地图知识。PLAN 或位置消息不能凭空建立队友地图。图容量是静态配置，溢出应显式报告，不能悄悄截掉合法节点后当成完整复现。

## 5. 通信、预算和预设：实际数据契约

### 5.1 消息格式

每包最多 256 字节，标准包头 16 字节，负载最多 240 字节。一次广播发送收费一次，不按接收人数重复扣费；不是按 JAX 张量的显存大小收费。

| 消息 | 内容 | 标准费用 |
|---|---|---|
| POSITION | x/y 坐标，各 uint16 | 20 字节，含头 |
| GOAL | 目标坐标，各 uint16 | 20 字节，含头 |
| PLAN | 生成位置、目标、有效长度、H 个坐标槽位 | H=5 时 45 字节，含头 |
| MAP_DELTA | 条目数＋坐标与占据状态，每项 5 字节，最多 47 项 | `17 + 5×条目数` 字节 |
| CUSTOM | 用户编码的 uint8 负载 | 实际头＋负载长度，需自行解码 |
| 显式转发 | 包含原作者、生成时间等来源信息 | 转发额外封装及本次发送均计费 |

MAP_DELTA 是栅格状态集合，不是免费完整地图广播；按本地观测新近程度及确定性顺序选择，无 ACK 时用游标轮转，不假设接收者已经收到某条历史消息。

自定义嵌入必须量化／序列化并计费，不能在通信接口外直接共享连续张量。当前内置 A/B 并未自动支持任意自定义载荷或定向接收者动作头。

### 5.2 扣费和故障

- `attempt`：合法且足额的发射尝试即扣费，即便全部接收失败。
- `success`：至少一名目标接收者实际收到才扣费；仍预先要求足额预算。
- 无效包或预算不足不发射、不扣费；预算耗尽后仍可移动、感知和接收。
- 正常链路只应用物理信号；随机丢包在可达链路上进一步丢弃；突发断联隔离选定机器人一段时间。
- 故障不自动清空记忆，不免费通知策略故障类别，也不隐式重传或多跳扩散。

### 5.3 可选预设

| 类别 | 已实现选项 |
|---|---|
| 奖励 | `coverage_delta`、`coverage_distance`、`sparse_success`、`ir2_individual`、自定义注册 |
| 信号 | `attenuation`、`ideal`、`range`、`los_range`、`ir2`、自定义注册 |
| 交换 | 广播、显式地址集合 |
| 扣费 | 尝试扣费、成功扣费 |
| 发送策略 | 方法动作、禁止、每次、周期、自定义注册 |
| 地图融合 | 开／关，均禁止免费读取队友真值 |

重要限制：`ir2_individual` 对齐的是个体奖励公式，不含原版整轮结束统一加分，因此不能称完整原版奖励；`attenuation` 与 `ir2` 的障碍计算不同，当前配置默认是前者。`ideal` 取消物理距离限制，但不取消预算和外部故障。自定义函数必须满足 JAX 纯函数、固定形状和显式随机数契约。

### 5.4 当前事件时序

1. 读取当前行动者本地地图、图和已送达消息。
2. 选邻接目标，形成当前行动意图。
3. 以此时已有知识编码并锁定消息。
4. 完成本次移动，在终点感知并更新本地图。
5. 根据移动后的发射位置和链路执行消息发送与计费。
6. 更新覆盖、奖励、事件计数和结束标记。

因此：POSITION 的值是生成时的位置，不应称为到达时的最新位置；本次新感知的地图不能出现在此前已锁定的包里。若未来要发送“移动后的当前位置＋最新地图”，必须明确改变锁包时刻并更新相应训练／评测契约，不能只换消息名称。

## 6. A 的已实现网络、训练流程及实际启用项

### 6.1 图导航网络与通信分支

当前 `ir2_graph` 分支的信息流为：

```text
六维节点特征＋图邻接＋当前节点＋掩码
    → 6 层图注意力编码器（128 维、8 头）
    → 当前节点解码与候选节点特征
    → pointer logits
    → 下一跳动作

图上下文＋自身扩展特征＋队友估计特征
    → ObservationEncoder → GRU（256 维）
    → 通信发送门控／消息类型头
```

**关键实现事实：图分支的下一跳 logits 直接由 GraphPolicy 输出。预算、队友计划估计与 GRU 记忆没有直接反馈到这条 pointer 打分路径。** `candidate_attention=true` 并不意味着图分支启用了旧非图分支的候选—队友注意力。

这不意味着通信完全不能影响动作：实际收到的地图和位置可以改变图观测、占据／会合等特征，从而间接影响导航。但不能声称现有图策略会直接利用计划预测器给出的意图，或根据剩余预算重新权衡去哪里。

最近配置固定通信，通信概率不进入 PPO 策略损失。因此上述扩展 GRU／通信头不是最近这条配置里学习导航决策的有效通路。网络容器里存在这些模块，不等于相关参数已被任务有效训练。

Critic 为独立的集中式价值网络，编码地图通道、机器人状态及全局特征，输出当前事件的团队价值。特权信息不应作为分散 Actor 的输入。

### 6.2 真实采集与更新

最近设置：16 个物理环境；通常每路 128 个有序机器人事件，组成 2,048 个有效真实动作的逻辑批。终止、补齐等情况由有效掩码与配额处理。

每批流程：

1. 使用冻结的当前参数在 JAX 环境采集，保存实际观测、动作、候选／掩码、旧 log-prob、奖励和记忆边界。
2. 在有序团队事件轴上计算 GAE，再按各机器人有效历史组织循环序列。
3. 序列长度 32，每个 PPO 小批 8 条序列；最多重复 4 个 epoch，并受目标 KL=0.02 提前停止约束。
4. 每个小批都执行一次参数更新。因此“4 个 epoch”不等于“一批数据只更新 4 次”；实际步数取决于序列数、有效掩码和 KL 停止。
5. 可选计划预测器在 PPO 阶段之后更新；最近配置关闭该学习。
6. 保存可恢复检查点；按录像／验证调度执行额外工作。

当前主机循环仍分阶段组织采集、更新和保存。**环境副本采集已经并行，但没有实现采集、优化、落盘三者持续异步重叠的完整流水线。**

## 7. 队友计划预测器：代码已经有，研究语义尚未闭合

### 7.1 输入、记忆、输出和监督

现有模型为分类随机隐状态 RSSM 风格结构：GRU 隐藏维度 256，默认 16 个分类变量、每个 16 类；每个接收者—队友对保留独立状态，参数共享。

- 输入：实际收到的位置／目标／PLAN、字段新鲜度掩码、消息年龄、自身位置与目标、预算以及本地已知区域比例。
- 新消息到达：用可用测量形成后验；只有位置消息时不能伪造完整计划测量。
- 没有新消息：由历史和自身上下文推进先验，不把训练真值塞入执行输入。
- 输出：归一化目标坐标、计划点坐标、方差、有效长度分布、最近消息时刻和缺失标记。
- 损失：坐标高斯 NLL、长度交叉熵、先验／后验分类 KL。
- 标签：队友在对应事件截面最新已生成的意图快照，不是未来重新规划后真实执行的轨迹。

### 7.2 当前存在的两个实质问题

**问题一：目标语义已经退化为单步行动结果。**

`navigate_edge` 只承诺本次选中的邻接端点；移动时 PLAN 有效长度为 1，等待时为 0。5 个存储槽位会填相同端点，但后 4 个无效，不能解释成 5 步计划。发送又发生在移动之后，所以成功收到时端点已到达。

举例：机器人从 P 选择 Q，消息锁定为“P → Q”；机器人移动到 Q，之后发送；队友收到的是已经发生的一跳，而不是“Q 之后打算去哪里”。这种信息不一定毫无价值，但不符合原先多步计划想象的叙述。

**问题二：预测结果没有直接进入当前图导航打分。**

即便以后把预测器训练好，按当前图分支，估计值进入扩展编码与通信分支，却没有直接改变下一跳 pointer logits。必须明确设计一个可验证的决策使用通路，否则预测误差降低并不说明探索策略能利用它。

因此，不能只把 `neighbor_estimator` 从 `zoh` 改为 `predict` 就宣称修复完成。当前预测器未启用不是唯一问题，通信目标语义和网络接入都需要审查。

## 8. B 的已实现内容与缺少的证据

代码包括：环境 RSSM、真实回放、世界模型监督损失、后验起点推断、想象状态、想象 Actor-Critic 更新、真实环境评估、恢复与诊断字段。

模型目标包括局部地图／感知变化、机器人状态、消息送达、奖励和 continuation。预算、包长、时间与行动顺序等已知规则在想象中精确推进；学习模型负责未知动态部分。想象状态也需要更新各机器人的本地知识和图，不能无限复用起点候选。

历史上有 B 的短程训练、想象更新和回放恢复验收记录；随后图观测改版有 B 图回放检查。但：

- 当前没有 B 训练进程。
- 最新 16 路 A 的内存／稳定性验收不能覆盖 B。
- 历史旧地图／旧动作版本的 B 数字不能作为当前图环境的效果与吞吐。
- 当前没有充分证据证明 B 的模型在原尺寸未知地图上具有可靠多步预测能力。
- 没有正式配对结果证明 B 比 A 更省真实交互或获得更好探索表现。
- A 的消息语义与输入通路问题同样会影响 B，世界模型不会自动消除它们。

B 还存在模型误差累积、感知预测不一致、利用模型漏洞等方法风险。它们是待检验问题，不能以已有 API 或训练 loss 下降替代真实环境结果。

- 地图加载、审计、连通区域预处理、清单调度。

## 12. 拟议修订路线：供讨论，尚未实施

### 12.1 先建立可解释的 A 基础版

建议暂时把学习任务收敛为：固定清晰的通信协议，只学习探索动作，先验证策略能够利用共享知识。

候选方案是以位置与地图增量为主要消息，使用成功收到的信息更新本地知识／可选融合图；停止把已执行端点称为未来多步计划。这里的“位置＋地图”是语义方向，**不是已经存在的组合包**：现有标准一次动作发送一种包，是否交替发送还是定义组合包，需要先明确格式与字节账本。

同样，现有 `receiver_map_communication.json` 采用的是既有 PLAN／MAP／MAP／POSITION 周期，不是已实现的全新“当前位置＋最新地图”方案，不能只切换配置文件就宣布本轮修订完成。

需要共同决定：

1. 消息反映决策前知识，还是移动／感知后的状态？两者均可定义，但必须有一致的时间戳与因果顺序。
2. 采用位置／地图交替消息、组合包，还是地图优先策略？固定频率和字节预算如何公平匹配？
3. 保留严格 IR2 pointer 作为基线，同时另设预算／队友意图可条件化的扩展策略，还是本轮只做地图通信？
4. 是否加入原版 SAC 或其他成熟训练器的受控基线，以区分环境与优化算法问题？这是待讨论范围，不是本次已经决定扩写代码。

### 12.2 若保留计划通信，先定义真正的计划

可讨论的计划包括尚未执行的下一跳目标，或明确承诺规则下的有限多跳路径。一跳动作接口不强迫发送多跳计划；反之，序列格式有 5 个槽位也不等于策略承诺未来 5 次动作。

必须定义生成时刻、预计执行时刻、允许重规划条件、有效期、旧消息处理和计费，并设计接收者如何使用它影响导航。没有稳定目标语义之前，不应继续训练计划预测器。

### 12.3 分阶段验证

| 阶段 | 工作 | 进入下一阶段的依据 |
|---|---|---|
| 0 | 冻结消息语义、时序和导航输入通路 | 能逐事件解释“发送什么、何时知道、影响哪个动作” |
| 1 | 最小修改、必要集成检查，新身份实验 | 消息、预算、图融合与恢复无语义冲突 |
| 2 | A 固定通信训练与配对验证 | 在固定验证地图上有可解释学习曲线，优于无通信是否成立如实报告 |
| 3 | 可选意图预测／学习发送 | 在同预算下比保持旧信息或固定规则有增益；否则保留负结果 |
| 4 | B 世界模型与想象训练 | 多步误差可接受，真实环境收益与额外交互／算力成本均被记录 |
| 5 | 正式 benchmark | 冻结方法和矩阵，完成声明的重复与场景，发布结果和失败案例 |

因消息／策略输入语义变化，新训练应建立新实验身份。旧检查点现已按用户要求删除，无法继续沿用；未来若另行引入预训练参数，应明确来源并作为显式迁移实验单列。**本轮尚未开始这次算法修改或重新训练。**

## 13. 必要验收与测试策略

遵循只做必要检查的要求，不为文案、低影响清理或每次小改动重复全套测试。

### 13.1 语义与实现验收

- 给定同样局部知识和邻接动作，动作必须一跳到达，不能恢复全图 BFS 截断运动。
- 给定消息在事件 e 生成，包不得包含 e 之后才观测到的信息，除非正式改写生成时序。
- 给定预算不足，发送拒绝；给定合法发送失败，按所选账本模式计算费用。
- 给定无 MAP_DELTA 送达，不能凭 PLAN 或真实队友地图增加接收者地图知识。
- 给定相同图观测、不同计划估计，当前严格基线的导航 logits 应保持其现有独立性；若新增条件化策略，则应验证存在有效信息通路，但不要求每次扰动必改变最终动作。
- 给定中途恢复，环境状态、计数器、参数版本和消息记忆应与保存点一致。

### 13.2 学习与比较验收

- 独立固定验证集，报告零通信／固定地图通信／待评估方法的配对结果。
- 训练回报、梯度范数、KL 与参数变化用于诊断，不能取代验证覆盖率与成功率。
- 同时展示典型与失败轨迹，记录起点、消息、预算、动作和网络版本。
- 先观察是否有可复现收益，再扩大训练；没有收益时优先排查信息使用和训练设计，不默认靠增加时长解决。
- 消融按所要回答的问题设计：同一策略屏蔽消息可以测即时依赖；分别训练无通信与有通信策略才能比较各条件可达到的性能。两种实验不能互相替代。
- PPO/SAC、A/B 的交互量、更新量与墙钟时间分别报告，避免把不同训练量混为公平对照。

### 13.3 性能验收

固定源码、地图、机器人数量、并行数和动作／参数，区分编译、reset、采集、优化、保存与录像。预热后同步设备计时。扩大并行先做短程完整闭环，不把纯采集测试当成长期训练稳定性证明。

## 14. 外部讨论建议优先回答的问题

1. **benchmark 的第一研究问题是什么？** 受限地图交换、失联意图估计，还是世界模型样本效率？第一版是否需要全部承担？
2. **消息最小有效内容是什么？** 对 IR2 一跳探索，位置＋地图能否构成足够强的基础，意图应定义为下一跳还是更长期分工？
3. **需要如何修改导航网络？** 保留纯 IR2 图策略作对照，同时加入独立上下文通路，是否比改变六维节点语义更清晰？
4. **谁来保证计划的稳定性？** 每步可重规划的目标，应该被建模为动作预测、意图预测还是承诺计划？
5. **预测器到底解决什么缺失？** 缺位置、缺地图、缺目标，还是缺任务分配？是否需要为不同缺失采用不同估计器？
6. **训练算法基线如何选择？** 是否应先用原版成熟训练流程得到可靠通信基线，再考虑 PPO 与世界模型？
7. **B 的预测任务是否过重？** 是否有必要学习高维感知变化，还是应先明确更有限且可验证的想象范围？
8. **怎样定义“协作学会了”？** 覆盖 AUC、完成率、重复探索、恢复能力与通信成本之间如何形成预先声明的判断标准？
9. **有限时间先交付什么？** 环境与强基线、方法验证还是完整大矩阵，应形成明确且诚实的阶段交付范围。

希望讨论得到的输出不是立即增加更多模块，而是冻结一套能解释、能验证的消息协议、信息通路、训练基线和实验优先级。
