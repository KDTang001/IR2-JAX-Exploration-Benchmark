# Phase 4：基线与统一评测验收

日期：2026-11-14。目标运行环境为指定服务器的 conda `ex`、Linux、JAX/CUDA、H100；Windows 仅做源码整理、静态检查及原权重张量提取。没有启动训练，没有恢复暂停的 A/B 世界模型实验。

**声明范围的 Phase 4 功能验收通过。** 312 个主任务、10,112 个有效 agent 事件均无执行错误和非法动作；另一个严格规则反例按预期返回环境错误。最终运行结果与源码身份见配套 [机器证据](evidence/phase4-20261114.json) 和 [逐任务数据](evidence/phase4-episodes-20261114.csv)。

## 1. 本阶段实现的基线

共八种固定方法，使用同一 JAX 环境、局部知识边界、一跳动作、标准 codec、预算、信号模型和独立故障条件。

| 导航 | 关闭通信 | 固定 PLAN | 固定 MAP_DELTA | 固定混合消息 |
| --- | --- | --- | --- | --- |
| 最近前沿 | `nf_off` | `nf_plan` | `nf_map` | `nf_mixed` |
| 原版权重适配策略 | `ir2_off` | `ir2_plan` | `ir2_map` | `ir2_mixed` |

最近前沿仅使用接收方已知图，从当前位置寻找图最短距离最近的有 utility 节点，执行路径的第一条合法边；坐标顺序解除并列。没有可达前沿时按边长、坐标选择最近的合法邻边，不能请求已被屏蔽的原地等待。遵守 IR2 的节点零号/邻接动作屏蔽，不以穿越未知区域的全图真值 BFS 代替局部决策。旧 `ir2_one_hop` 模式保留原有行为，本次只修正 `ir2_graph` 分支。

适配策略复用已有六层图注意力与 pointer 的 `GraphPolicy`，加载原版真实的 90 个 float32 策略张量，greedy 选择合法边；没有随机初始化冒充原版权重。预算和通信不会被偷偷加入原 pointer 的 logits。收到的真实 PLAN/MAP/POSITION 通过环境已有局部地图、队友接触和会合特征影响后续观测。

三种启用通信的方法每四次自身行动发送一次，从第零轮开始；混合方式循环 `PLAN → MAP_DELTA → MAP_DELTA → POSITION`。这是明确的固定调度基线，未学习发信时机、消息类型或队友预测器。`training_seed=-1` 是无新增训练的固定策略标记。

主配置为 `configs/benchmark.json`：IR2 图导航、原版传感器半径 80、图容量/补齐 400、每机器人 8 KiB、attempt 扣费、broadcast、`signal_model=ir2`、global graph fusion 关闭、`rendezvous_mode=reachable_only`。自身历史节点始终保留。Normal 只关闭外部故障，仍须满足物理信号阈值，不能解读为所有机器人总能通信。

### 部分通信下的会合规则

实测发现合法的 PLAN 与稀疏 MAP 消息不能保证接收方已知区域包含队友位置到自身的路径。旧规则在开发地图第 12 个事件失败：机器人位于 `[6,23]`，队友估计位于 `[20,18]`，后者仍是接收方未知格。对同一 10 节点图，实际原版与 JAX 的修复边完全一致，二者均无法到达该估计；这不是 JAX A* 数值或边生成差异。

用户据此确认主配置使用 `reachable_only`：仍执行原来的直接/对称/重建图搜索；某个队友的估计不可达时，该队友不贡献会合效用，继续处理其余可达队友，自身附近的效用抑制仍适用。不伪造路径、不查询全局真值、不丢弃整个 episode。探索动作仍须从合法一跳边选择。

`strict_ir2` 保留原版中止规则，且仍是 `HostConfig` 与底层 solver 的默认值；专用 `configs/benchmark_strict_ir2.json` 与主配置仅此字段不同。原有 parity 测试继续检验严格模式。主配置的新行为是处理部分消息的 **Benchmark 扩展**，不能宣称这一分支与原版 IR2 完全等价。额外的同种子严格规则对照保留该失败为 `environment_error`，不得计为 timeout 或成功。

严格对照另有匹配的 `configs/evaluation/benchmark_strict_ir2.json`，仅将 suite 的 base_config 指向严格配置；复用同一八方法清单。这样用户选择严格配置后，规划和报告都能核对相应的配置身份，不会与主配置混用完成数。本阶段没有运行完整严格对照矩阵。

## 3. 统一结果与通信账本

原有 `spent` 只代表费用；success 扣费下，发出但没有送达的包仍有物理流量。本次新增 `StepInfo.emitted_length` 和对应事件遥测，以实际包长记录 eligible 的发射；冻结事件发射为零。

每条真实评测 trace 额外保存实际 `packet_buffer`、`physical_links`、`external_links`。结果分别报告 emitted bytes、spent bytes、按接收副本计算的 delivered payload bytes。预算利用率使用 spent；历史结果缺少费用时保持缺失，不能用发射量猜测费用。旧 attempt trace 可以兼容，缺少发射遥测的 success-charge trace 明确拒绝。

所有方法复用现有 task/scenario manifest、bounded batch runner、错误分类和报告入口。地图/出生/故障种子和隔离机器人身份按场景冻结，checkpoint 内容摘要进入方法身份。错配或损坏的结果不能计入完成数；execution error、OOM 和 timeout 分开保留。报告区分 `requested_manifest_complete` 与 `formal_complete`。

## 4. 验收范围与统计规则

小型功能矩阵预先声明 312 个唯一任务：

- 288 个配对任务：6 张地图 × 2 个场景种子 × Normal / Dropout(p=0.3) / Burst 三种独立条件 × 8 方法。
- 16 个机器人数量检查：原尺寸 IR2 Hybrid、N=4/6，各八方法。
- 8 个预算零对照：同一开发地图、八方法。

另有一个不进入主评分的严格会合规则反例：同地图、同出生/故障种子、同 `ir2_mixed`，只切换会合规则；期望其显式返回环境错误，用于验证原规则仍被保留。

地图包括一张可独立计算的 64×64 开发地图，以及按 occupancy hash 固定选取的原尺寸 IR2 Complex/Corridor/Hybrid、程序化 Rooms、OOD narrow Hybrid。原尺寸配置保持半径 80、50×50 基础图和 400 节点容量；只将本轮功能验收时长声明为 16 轮，N=4/6 为 8 轮。开发地图使用单独记录的缩小传感器/图尺度。Burst 从第 4 轮开始，持续 4 轮；正常、丢包、突发互不混用。预算零条件与其余预算条件分开计分。

每个固定策略的分数先对场景取平均，再在地图族内等权平均地图，最后等权平均地图族。固定权重条件下置信区间以地图为抽样单位，场景重复不是新的独立训练重复。本轮每族只有一张地图，不发布置信区间，也不用于判断算法排名或通信增益。

完整声明配置为 `configs/evaluation/benchmark.json`：1,328 张 test/OOD 地图 × 3 场景种子 × N=2/4/6 × 4 预算 × 6 个独立故障条件 × 8 方法，共 **2,294,784** episodes。它与旧 `core.json` 的 A/B 研究矩阵分开；本阶段没有执行完整矩阵，没有宣称正式实验完成。

这些 312 条轨迹均为 `timeout`：本轮只运行了预先声明的 16/8 轮，不能把功能验收通过写成 99% 探索成功率通过。有效事件包括合法等待，不等于每次都发生位移。本轮实际发射/扣费均为 270,828 字节（attempt 模式），送达负载按接收副本合计 232,513 字节。

独立重算按两个互不重叠的冻结子清单执行，281+31=312；最终核对所有 result_id 与主清单恰好相等。该程序还正确拒绝旧轮次中一条已知非法动作记录。主矩阵、严格反例、续跑和报告的计时为 3,524.0 秒，不含此前的参考推理与 CLI 首次检查；包含大量冷编译，不能据此计算稳态吞吐或宣称 GPU 加速倍数。

验收保留了失败历史：

1. 首批 160 项中 152 通过、8 失败。六项旧策略测试在强制 CUDA 会话里显式要求 CPU，改为当前目标设备；一项 softmax 求和断言使用了过紧的 float32 默认容差，按两个 epsilon 检查；一项旧 manifest 测试未区分含实现摘要的新身份与真实旧身份，修正了夹具。针对复验 66 项全部在 CUDA 通过，未降低原随机权重策略数值对照要求。
2. 真实预训练权重在 400 节点图上触发早期 FP32 log-prob 阈值。十个输入独立复查显示 FP64 最大误差约 `3.05e-13`，屏蔽和 greedy 决策全部相同；FP32 最大 log-prob 差约 `1.34e-4`、概率差约 `3.13e-5`。最终验收同时要求 FP64 `1e-10` 对照、FP32 log-prob 绝对差 `2e-4`、概率绝对差 `5e-5`，并要求屏蔽和 greedy 决策完全一致。只调整对照验收的数值规则，生产网络保持 float32 与 HIGHEST matmul。
3. 只读复核发现结果身份核对不完整，以及 success/timeout 缺失必要分数也可能被当成完成。已在公共结果读取边界加强核对；校验和正确但任务元数据不一致或必要指标不合法的记录必须拒绝。
4. 部分地图通信触发原版会合不可达分支；原版实际代码对照复现，随后按用户确认增加主配置的 `reachable_only` 选项，并保留严格规则反例。另修复环境图失败被误归为模型错误的分类；没有把所有 ValueError 一概归入环境错误。
5. 结果绑定复验首批 127 项中 126 通过；唯一失败来自新补全夹具内的 tuple 经 JSON 变为 list 后仍拿内存字典比较。改为逐字比较原始 JSON 后单项通过，保留了该次原始 XML。临时部署 helper 的旧 Python tar API 和字符串生成错误发生在测试启动前，已修正；不计入功能测试通过数。
6. v3 逐事件核查发现最近前沿在没有可达前沿时请求了非法等待。中止本轮自有验收进程，保留部分结果，不将其混入最终评分；将 fallback 改为最近合法邻边，并让回归实际调用导航器验证动作合法。最终独立 replay 同时检查零非法动作、未行动队友位置不变，以及原版碰撞函数确认执行边不穿过接收方未知/占据区域。

独立 replay 从原 PNG、出生种子、原版 `sensor.py`、原版信号模型和 trace 的位置/原始 wire 重建覆盖、AUC、包头/调度、费用、送达负载、冷启动、overlap 与分配集中度，不调用生产指标函数。Normal/Burst 的外部掩码独立重算；Dropout 条件使用记录的外生随机实现并核对方法间配对一致，随机采样器本身的独立验收归 Phase 2，不能称为完整独立 PRNG 重现。

生产源码变化使实现摘要更新，因此同步重新冻结原 25 个 validation 场景；地图、出生/故障种子、机器人数量、时长及 8 KiB 预算保持不变。配置表示显式补入默认 `rendezvous_mode=strict_ir2`，继承规则不变；配置摘要、实现摘要和派生场景 ID 因而更新。这不是重新挑选有利验证集。

这 25 场保留原研究配置用于回归，本轮固定参考策略没有据此选模。后续新增可学习基线时，需另外冻结与其主配置匹配的 validation 工作负载，不得据 test/OOD 选权重。
