## 当前可支持的成本判断

H100 512/N=2/B=1 的配对四事件短段最近前沿为 23.50 事件/s、IR2 adapted 为
22.98 事件/s，相对同服务器固定 8 核 CPU 约 62 倍。这不是成熟图上的完整回合吞吐。
两路 H100 进程的 78 项完整回合加六次暖重复，共耗时 23,135.12 秒（6.43 小时），
实际测量 101,759 个有效事件；其间存在安装检查的设备共享，不能当作隔离的硬件速率。

| 桶/N | 主配置首次完整调用耗时中位数 | 正常 mixed 最近前沿暖调用 | 正常 mixed IR2 暖调用 |
| --- | ---: | ---: | ---: |
| 512/2 | 182.06 s | 248.12 s / 659 事件 | 236.78 s / 322 事件 |
| 768/4 | 337.74 s | 770.71 s / 2048 事件 | 1081.15 s / 393 事件 |
| 1024/6 | 608.58 s | 3122.26 s / 3072 事件 | 3287.94 s / 1196 事件 |

这些值包含实际验收时的并发影响；不能将它们直接当作独占 GPU 的延迟，也不能以短段
吞吐乘 B 推算完整回合加速。即使仅按短段 23.50 事件/s 达到最坏事件上限，也约需
2315 天串行事件时间；这只是展示数量级的条件计算，不是正式运行预测。

存储已有精确实物：78 项结果 JSON 共 135,361 字节，压缩轨迹共 4,594,413 字节，
平均合计约 60.64 KB/episode。若机械沿用这一均值，旧矩阵约为 139.15 GB（129.59 GiB），
另加日志、索引与统计产物。正式矩阵的更高预算和不同路线会改变压缩率，该值不是上限。

完整逐项耗时、事件数与字节数见 [78 项原始汇总](evidence/phase5-full-episode-summary.json)。
512/N=2 的 H100 初始最近前沿片段从 B=1 的 23.50 事件/s，增至 B=4 的 67.63 和
B=16 的 162.37 事件/s；16 路约为单路 6.91 倍。本例 NVML 进程显存峰值下界分别为
1810、9378、34484 MiB，JAX 分配峰值分别约 1.21、4.87、18.54 GB。
CPU 同例 B=16 超时，只保留已测阶段。全部 GPU 配置中 21 项完整、6 项 OOM，
后者恰为 768/1024 桶的全部 N 下 B=16。B=1/4 在三个桶和 N=2/4/6 均完整测量。
因此不能为正式矩阵统一假定 B=16；独占条件下的成熟图成本及未完成的 CPU 阶段/配置仍待另行安排，
也不能把短段扩展率套到整张正式矩阵。
三张验证地图不代表 1328 张正式地图的成本分布；估算必须给出该外推限制。
