# 协作训练设计与实施顺序

用户已批准分阶段实施，测试在完整阶段结束时集中运行。

## 训练定义

任务保持局部观测下的多机器人探索。执行端只使用自身地图、实际收到的消息、消息年龄和预算。集中式 critic 可使用训练特权信息。A 使用真实交互 PPO，B 使用世界模型想象更新。通信条件分别训练与评估。

先完成 recurrent PPO，再加入候选级消息交互。先以固定高频合法发包训练协作策略，随后冻结接收器和行动策略训练发送门控，最后进行受控联合微调。世界模型接入以真实策略能完成协作为前提。

## 第一阶段

- [x] 在现有 storage.py 中把真实采集结果按采集流和机器人分组，每段最多 32 次自身决策。保留环境事件顺序上的 GAE，不跨环境、机器人、采集边界传播记忆。
- [x] PPO 使用段首采集记忆作为截断边界，段内以当前参数重算 GRU，通过时间反向传播。尾部补齐仅用于固定形状，损失掩码排除补齐。
- [x] 同时接通 train_a.py 和 driver_a.py。已有单步 PPO 调用保留兼容。配置记录 sequence_length，设为 1 获得单步截断。新配置身份与旧 checkpoint 不同，需要启动新实验。
- [x] 集中验证延迟梯度、分组隔离、正常训练入口与恢复行为。训练结果与旧算法使用不同配置身份。

## 第二阶段

在现有 encoder 和 actor 内加入候选对队友消息的注意力。候选包括本地地图推导的可见前沿效用和路径代价。消息包含目标、轨迹、年龄和缺失信息。每个候选独立汇总相关队友，缺失消息严格屏蔽。模型结构改变时创建新配置身份并重新初始化，IR2 权重迁移须另行验证输入和动作兼容性。

候选作为 query，逐队友的有效消息作为 key/value，聚合结果参与该候选的打分。全缺失时聚合值为零，保证有限输出。当前 LocalObservation 没有独立的到访记录，本阶段采用现有局部地图与路径特征。结构验收检查缺失掩码、队友排列不变性和消息到候选分数的梯度，再用闭环留出地图检验实际协作。

具体实现复用现有 supercover 几何，以 min(sensor_radius, 8) 为局部效用半径，统计候选周围经过已知自由空间可见的前沿占圆盘目标点的比例。未知格和已知障碍均阻挡该估计，地图边界之外不计入前沿。该值是保守的局部信息增益特征。新架构由 candidate_attention 配置记录，A/B 共用接收器与特征。旧 checkpoint 元数据没有该字段时按 False 加载旧编码与网络，并通过架构字段区分评估缓存。

- [x] 接通候选级消息注意力、本地前沿效用与缺失消息掩码。
- [x] A/B 初始化、真实采集、想象输入及 checkpoint 推理使用一致的架构配置。
- [x] 验证全缺失、队友排列、消息梯度及本地墙体遮挡。梯度检查关闭原汇总编码器，确保梯度来自新增候选级分支。
- [x] 验证 A 真实更新、新旧 checkpoint 评估、B 想象更新以及新旧架构批量推理。

2026-11-09 第二阶段完成。必要检查覆盖 18 个不同用例。首轮 16 项通过，遮挡测试的候选数组与环境候选数不一致，修正测试数据后该项通过；另补验旧 B checkpoint 与强化后的注意力梯度检查，均通过。变更文件 Ruff 检查通过。生产代码没有增加新的模块。

## 第三阶段

复用 fixed communication 与 ZOH 入口预训练接收器，在实际信号模型下使用固定高频合法发包。课程从简单地图推进到复杂地图。逐步引入陈旧消息，正常链路、独立丢包和突发断联各自验收。随后冻结行动策略，使用任务收益和实际账本训练发送门控。门控阶段使用足够长的回报估计预算的机会成本。真实发送与静默分支仅抽样检查归因，不遍历所有候选。

门控只能使用发送者可知的发包历史。若协议没有确认包，发送者无法读到接收者真实缓存和实际丢包结果。PLAN 延续现有确定性编码。第一轮接收器训练采用固定 PLAN 类型，预算足够覆盖预训练阶段的合法发包；有限预算门控阶段继续使用既定账本规则。接收器在门控产生的实际消息分布上联合微调，避免仅适应高频消息。

首次接收器预训练使用 configs/a/receiver_pretrain.json 与 configs/receiver_pretrain.json。固定 PLAN 每次自身决策发送，账本、信号传播和真实送达继续由环境处理。预算 131072 字节，足以覆盖 512 次最大 256 字节包。采用 ZOH、正常链路、零启发式预热，从第一批数据更新 actor。16 路物理环境，逻辑批次 2048 个真实动作，每段最多 32 次自身决策。初始 256 个分配 episode 采用 IR2 easy 地图、4 个机器人，随后恢复完整 108 样本平衡周期。课程参数参与采样身份及 checkpoint 身份。

本轮训练配额 2000000 个真实动作，运行上限 48 小时。每 100000 个真实动作在固定的 25 条正常链路验证场景上评估。录像保存首集及每 64 集，每轮一帧、最多 513 帧、帧间隔 100 毫秒。新网络从新初始化开始，正式预算受限实验在接收器闭环效果验收后推进。

2026-11-09 第三阶段已启动独立的新训练，输出位于服务器 artifacts/receiver-pretrain-20261109/run。必要验收 8 项通过，耗时 242.95 秒，变更文件 Ruff 检查通过。验证集 25 条场景已重建为正常链路与充分预算，并检查占据图哈希与训练集无重叠。启动后已完成两批、4096 个真实动作，checkpoint 的 actor 优化步数为 8，优化器浮点状态平方和约 2.97e-5，确认存在实际梯度更新。第二批耗时 228.95 秒，采集 220.16 秒、更新 4.87 秒，约 8.95 个真实动作/秒。这是初期实测，尚未确认长期稳态吞吐；按该速度外推无法在 48 小时内完成 200 万动作，保持原配额和时间上限并如实记录实际完成量。协作效果仍待完整 episode 与固定验证集评估，不以梯度更新代替效果验收。

## 第四阶段

B 用同接口的真实数据学习转移，先检查通信导致的选点、覆盖和预算变化，再允许想象更新。报告真实评估覆盖率、完成率、重复覆盖、预算消耗及固定种子探索录像。预测 MSE 单独作为诊断。

## 依据与验收

ETCNet 提供先训练充分通信策略、再训练门控的顺序。IR2 提供图效用与地图课程。TarMAC 提供消息注意力，MAPPO 提供循环策略训练实现参照。上述组合是本项目的适配设计，性能须实测。

参考 https://arxiv.org/pdf/2010.04978 ，https://arxiv.org/html/2409.04730v3 ，https://proceedings.mlr.press/v97/das19a.html ，https://arxiv.org/abs/2103.01955 。

第一阶段验收关注时序梯度及训练正确性。后续阶段用留出地图的闭环探索评估接收器、发送门控与世界模型贡献。每阶段只增加能够覆盖已识别缺陷的测试，集中执行相关已有测试。

第一阶段采集边界使用截断记忆，能够学习的最长依赖受实际采集段长度限制。不同采集流产生的序列数量变化可能触发 JAX 重编译，正式性能测量需要同时记录编译时间和稳态吞吐。

2026-11-09 第一阶段验收在服务器 conda ex 中完成。test_actor.py、test_train_a.py、test_parallel_a.py 合计 19 项通过，用时 727.10 秒。覆盖真实更新、延迟梯度、机器人隔离、普通及原尺寸多地图池恢复。变更文件的 Ruff 检查通过。性能改善与协作效果留待后续闭环训练测量。
