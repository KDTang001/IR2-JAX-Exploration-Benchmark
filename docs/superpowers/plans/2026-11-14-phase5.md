# Phase 5: full episodes, performance, and reproduction

Baseline: `be8949ff8b6d25cee0891c48d128e8fee6cc44d3`.
Scope: limited engineering acceptance on the target Linux/H100 server. No policy
training, world-model runs, formal paper matrix, or automatic merge into main.

## Execution

1. Freeze validation-only representative map identities before execution: one
   retained map per native bucket (512, 768, 1024), deterministic hash order.
   Use N=2/4/6, the two navigation baselines and independent normal, dropout,
   and burst conditions. Every selected episode has the actual 512-round limit.
   Declare the exact limited manifest and budget/fusion probes before running.
2. First run the unchanged baseline for a full-length diagnostic. Record errors,
   graph occupancy/overflow, history, budget, faults, and true termination.
   Fix only demonstrated blockers, retain failure evidence, and run targeted
   regression checks. Never treat graph failure as timeout or successful score.
3. Reuse evaluator records, independent trace checks, and resume validation.
   Capture valid failure as an outcome; exploration success is not a gate.
4. Correct throughput units to actual active robot events. Run each key case in
   its own process, with synchronized cold/steady timing and explicit CPU
   affinity/threads, GPU memory and host RSS. Pair identical map/N/batch/workload
   on CPU and CUDA. Begin B=1, then B=4/16 after measured costs. Measure reset,
   scripted transitions, nearest-frontier and IR2-adapted execution separately
   from end-to-end loading/serialization. No learned-world-model timing.
5. Build/install the wheel outside the checkout, verify module origin, run
   doctor, complete an evaluation/report, and demonstrate interruption/resume.
   Use isolated Linux CPU and CUDA installations; preserve the existing `ex`
   environment. Document exact checkpoint acquisition/extraction/digests.
6. Publish compact raw evidence and three reports: full-episode acceptance,
   performance/reproduction, and formal experiment resources/proposed scope.
   Estimate the existing 2,294,784-episode declaration from observed costs;
   label any suggested smaller protocol as unapproved/versioned.
7. Review final changes and evidence; update roadmap and audit branch. Prepare
   a reviewable PR, leaving main untouched until release gates are satisfied.

## Ownership and verification

- Coordinator: fixed manifests, full episodes, scheduling, reports, publication.
- Performance worker: throughput measurement units and isolated process driver.
- Reproduction worker: wheel/installation workflow, provenance and documentation.
- Workers do not modify environment semantics or run GPU jobs without scheduling.
- Run only checks justified by changed behavior; do not repeat Phases 1–4.
- Retain original and corrected evidence identities. Do not download full map or
  model copies to the local project, and do not commit generated build caches.
- Respect the previously stated two-day experiment window; report measured
  failures/limits instead of silently reducing a declared matrix.
