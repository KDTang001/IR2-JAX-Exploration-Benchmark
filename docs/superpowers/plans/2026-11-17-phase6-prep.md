# Phase 6-Prep execution contract

Base: `d3d6c5fdec831de3076b7ede70e25b72108e59bf`; branch: `codex/phase6-prep`.
The user's approved scope is release/OOM repair, evidence-led performance work,
validation pilot preparation, and paper baseline/protocol design. No training.

## Boundaries

- Preserve Phase 1–5 evidence and A/B world-model/intent modules.
- Use new source snapshots, result identities and output directories.
- H100 measurement window: at most 14,400 seconds, including compilation,
  starting with the first new GPU process. Record a persistent deadline and
  terminate child measurement processes at that deadline. One GPU job at a time.
- Six initial profiles only: (512, N2), (768, N4), (1024, N6), each B1/B4.
  Do not retry the known large-map B16 allocation failures.
- Check shared-GPU occupancy before launching; record competing processes.
- Never launch the full 240-task pilot or a paper matrix in this phase.

## Work and evidence

1. Repair truthful source/distribution/runtime provenance and ValueError OOM
   classification; run focused regression tests and installed-wheel checks.
2. Freeze the unmodified base source and representative validation map identities.
   Capture synchronized timings, JAX GPU traces, compiler memory analysis and
   host/device memory, retaining raw evidence on the server.
3. Attribute bottlenecks from GPU operators/HLO metadata. Component probes are
   isolated workloads and must not be reported as additive full-step percentages.
4. Change only a measured dominant bottleneck. Pair old/new inputs and random
   keys; compare state, integer covered-cell counts, wire bytes, deliveries,
   actions and rewards. Keep an optimization only with measured benefit.
5. After package changes settle, freeze validation-only resource-pilot-v1:
   five families × one map × N4 × two budgets × three independent faults ×
   eight configurations = 240 episodes. Record map/config/source/task hashes.
   If time permits, predeclare and execute only a tiny full-episode cost subset.
6. Write the five requested reports, distinguishing measured results, remaining
   limits and unapproved paper-protocol choices. Run necessary targeted checks,
   commit and publish the new branch; do not merge main.

## Exit criteria

Trustworthy metadata, classified OOMs, six profile outcomes with raw evidence,
an accepted paired optimization or explicit measured no-change outcome, frozen
validation pilot identities, baseline fairness findings, and a conditional paper
protocol. Any incomplete measurement is reported explicitly, never imputed.
