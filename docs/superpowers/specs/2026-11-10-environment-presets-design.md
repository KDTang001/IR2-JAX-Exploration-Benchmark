# 奖励、通信与信号预设及自定义接口（已确认设计）

实施说明：原版整轮团队完成奖励无法在不改变当前单事件标量奖励契约的前提下严格复现。因此实际发布的原版公式预设命名为 `ir2_individual`，不包含该整轮奖励；信号预设 `ir2` 单独进行了数值对照。具体支持范围见 `docs/environment-presets.md`。

## 目的和边界

将当前固定机制提取为可选择、可组合、可扩展的配置。保留当前默认行为和旧配置文件兼容性；本轮不改出生、动作、观测和探索完成规则，不启动或重启训练。

采用“轻量函数接口 + 显式预设表”。不把全部选项塞入 step 中的大分支，也不引入动态插件加载框架。预设在环境构造时解析，函数在编译前绑定；设备运行期间不查注册表。

## 奖励

首批目标预设：

- `coverage_delta`：现有团队物理覆盖增量与事件成本，默认系数严格保持当前行为。
- `coverage_distance`：覆盖增量与实际移动距离成本，权重可配置。
- `sparse_success`：首次成功奖励与可选事件成本；超时不作为成功。
- `ir2`：对照原版的新前沿、探索效用、会合效用、距离和团队完成奖励。必须核对计算时点与团队奖励发放频率，完成必要对照后才能标为原版一致；不能只照搬系数。
- 自定义：输入明确的转移统计量，返回当前动作事件的标量奖励和固定形状分项统计。需新增统计量时显式扩展输入，不允许奖励函数修改环境状态。

训练奖励可由方法自定义；正式评估始终报告统一的覆盖率、距离、动作数、成功率、传输字节等指标，不能跨不同奖励定义比较 return。当前执行单位是有序单机器人事件，不在此次改动中引入同步联合动作或向量奖励。

## 通信：拆开四项配置

1. 内容编码：复用 POSITION、GOAL、PLAN、MAP_DELTA 和自定义字节编码；提供标准编码器供基线使用。学习到的特征先明确序列化格式与真实字节数，不能免费传递张量。较大地图以多包增量传输，不在一次动作中隐藏无限容量的完整地图同步。
2. 发送策略：不发送、每次发送、固定周期发送、方法自行决定。此项属于方法侧；环境规定允许的内容与传输约束。不同内容的轮换可由发送策略实现。
3. 交换方式：首批为当前一跳广播，以及显式收件人集合（单播是集合大小为一的情况）。保留显式转发能力，每次转发单独计费；不增加自动多跳传播。
4. 预算规则：当前按有效发送尝试扣除一次实际包长，或至少一个接收方成功送达才扣除一次包长。两者均发送前检查余额；成功指物理送达，不依赖接收策略是否使用消息。无通信仍沿用同一账本，实际花费为零。

预算包含包头和有效负载；广播的一次费用不随接收者数量变化。地址校验、余额检查、发送与接收日志由环境统一执行，自定义方法不能绕过。消息只来自发送方决策时的本地信息。只有收到真实地图内容才能更新队友地图或融合图；位置、计划和特征消息不自动授权地图访问。

## 信号与外部故障

首批目标预设：

- `ideal`：所有活跃机器人间物理链路可用，仍受预算、发送策略和独立故障条件约束。
- `range`：固定通信半径。
- `los_range`：视线无遮挡并满足距离限制，明确角点与障碍判定。
- `attenuation`：现有自由空间/障碍路径衰减公式；将发射功率、参考损耗、衰减系数等现有参数暴露为配置。
- `ir2`：复现原版信号计算、阈值边界与随机参数生命周期；对照通过前不宣称等价。
- 自定义：以地图、端点、明确随机键和参数为输入，返回链路可用性及诊断量。物理模型允许访问真实障碍图，该图不传给策略。没有物理信号强度定义的模型使用显式有效标志，不伪造 dBm。

正常链路、随机丢包、突发断联继续为互斥的独立外部测试条件，不混合为一个预设。物理链路可用性与外部故障分别记录。

## 自定义契约和复现

- 自定义实现通过 Python API 显式注册有名称和版本的函数；配置只引用已注册名称，不从 JSON 任意加载代码。
- 函数必须为可 jit/vmap 的纯函数；随机性通过显式 key 传递，数组容量固定。改变结构或实现可以重新编译，不承诺任意预设共用一份编译结果。
- 方法侧编码器、解码器与发送策略仅获得局部观测和已送达消息；环境侧奖励、物理信号与预算执行拥有各自必需的内部数据。
- 配置载入时拒绝未知预设、无效参数和不支持的组合，不静默回退。MAP 内容才能触发图融合的限制在环境内执行。
- 保存完整展开配置、实现名称/版本及源码修订信息到训练与评估产物；恢复训练时拒绝未显式处理的语义不兼容配置。
- 同一正式测试条件下，各方法使用相同的物理信号、故障、容量和预算扣费规则。不同环境预设分开报告；方法可自行选择奖励和协议内的消息策略。

## 实施顺序和必要验证

1. 提取现有默认实现并接通配置及记录，验证旧配置下状态、奖励、字节和投递结果不变。
2. 添加上述简单预设与自定义接口，完成一组有遮挡、丢包、余额不足、显式收件人和未送达地图的集成场景，并检查 jit/vmap 一致性。
3. 单独移植原版 IR2 奖励和信号，进行有针对性的原版对照后再发布这两个预设。

不为每次局部改动重复全量测试；不新增训练实验来证明配置切换本身可用。更新一个使用说明和最小自定义示例即可，不建立额外实验管理框架。
