# 通信受限多机器人探索 Benchmark：设计决策记录

更新日期：2026-11-05（Asia/Shanghai）

本文记录讨论中已经明确选择的方向，并区分建议规则与待定事项。本文不是实现完成报告，也不是已冻结的完整评测规范。

已形成并于 2026-11-05 获得用户整体批准：[2026-11-05 设计稿](superpowers/specs/2026-11-05-communication-exploration-benchmark-design.md)。下文保留逐项讨论时的历史状态；涉及原待定事项时，以获批设计稿为准，数值仍属于需要预实验校准的默认值。

## 1. 已确认的定位与交付范围

- 构建新的 benchmark，参考 IR2 的任务与地图，不以逐项忠实移植 IR2 为目标。
- 以 JAX 原生环境为技术方向，支持纯函数状态转移、编译和环境副本批量执行。
- 第一版同时包含环境、评测闭环、学习式探索策略和计划预测模型。
- 第一版包含两条学习路线：A 为计划预测辅助真实环境交互训练，B 为通过世界模型想象轨迹训练策略；两者均为必需交付，不把 B 仅列为未来扩展。
- 环境接口保持方法中立，允许启发式、学习式探索、学习式通信和计划预测方法参评。
- 吞吐量必须实际测量，不把其他 JAX 平台的加速倍数当作本项目性能保证。

## 2. 已确认的任务与信息权限

| 项目 | 已确认选择 |
| --- | --- |
| 主任务 | 团队联合覆盖：以所有机器人实际观测区域的并集评价探索成果 |
| 联合地图 | 只供评测及明确声明的集中训练用途，不能作为分散执行策略的观测 |
| 训练方式 | 允许集中训练、分散执行；披露使用的额外训练信息 |
| 执行信息 | 本地感知、历史记忆及实际收到的消息 |
| 感知模型 | 360°、有限半径、带遮挡的理想栅格可见区域 |
| 动作 | 选择本地地图中已知且可达的航点，由统一导航器执行 |
| 行动顺序 | 固定机器人编号依次行动，每台行动后更新环境 |
| 移动范围 | 每次行动朝航点最多移动固定距离 d_max，而非一次直接到达任意远目标 |
| 碰撞规则 | 禁止穿越墙体；不模拟机器人之间的实体碰撞 |

同一轮中，后行动机器人可以利用前面机器人实际传递给它的新信息。环境更新本身不意味着免费共享地图。机器人先后执行属于有序事件语义，不能把机器人直接作为互不依赖的环境副本批量执行。

## 3. 已确认的通信预算与载荷接口

- 所有机器人间消息统一计费，按实际编码后的字节数核算。
- 每台机器人拥有独立、初始等额、不可转让的预算。
- 方法可以自定义消息载荷，环境负责传输与成本核算。
- 同时提供标准编码器，供基线复用固定语义消息。
- 标准编码器拟覆盖位置、目标航点、计划序列和地图增量；具体字段和精度在接口规范中确定。
- 自定义载荷不能通过对象引用、共享可变状态或其他免费通道访问发送方内部信息。
- 链路可用本身不等于收到邻居计划，计划信息必须经过显式消息传输。

### 已确认的通信决策方式

- 主方法学习何时发送及发送什么内容，与探索决策共同考虑通信预算。
- 保留统一固定通信规则作为对照，避免所有收益都归因于计划预测。
- 固定规则的发送间隔、消息选择及预算不足时的行为需要在完整规格中确定。

建议采用“固定/学习式通信 × ZOH/学习式计划预测”的交叉对照，另设不使用邻居计划的辅助基线。各组保持相同预算上限、消息计费和可用信息权限；相同预算上限不代表实际消耗相同，须同时报告实际通信成本与探索效率。该对照矩阵是待整体审阅的实验建议。

## 4. 已确认的退化评测

三个条件独立评测，第一版不叠加随机丢包和突发断联：

| 条件 | 定义 |
| --- | --- |
| 正常链路 | 使用基础信号强度通信模型，无额外故障；仍可能因距离或遮挡断联 |
| 随机丢包 | 在基础链路原本可送达时，额外施加随机丢包 |
| 局部突发断联 | 在规定区间隔离部分机器人，其余机器人之间仍按基础链路模型通信 |

已选择局部机器人隔离，而不是全队通信同时中断。被隔离机器人数量、选择方式、故障开始轮次及持续轮数尚未定值。

## 5. 已确认的地图方案

- 结合 IR2 现有地图与程序化地图。
- 采用混合训练：IR2 原训练地图加程序化训练地图。
- 分别报告 IR2 参考测试集和程序化测试集的结果。
- 不把原有 IR2 测试地图用于训练或调参。

当前仓库已核实存在以下目录：

- DungeonMaps/train/easy
- DungeonMaps/train/difficult
- DungeonMaps/test/complex
- DungeonMaps/test/corridor
- DungeonMaps/test/hybrid

建议程序化测试区分“相同生成规则的新实例”和“训练时未见的结构参数范围”。固定生成器版本、参数、种子及地图清单，并检查重复地图；仅分离随机种子不足以保证结构不同。

由于完成条件、感知和通信机制已改变，不能直接将本 benchmark 的分数与 IR2 论文数字比较；需要在新协议下运行基线。

## 6. 已确认的计划表示

采用“目标航点 + 短期规划路径”：

- 目标是机器人当前选择的航点。
- 路径表示机器人当下根据本地地图规划的后续 H 次自身行动的计划位置。
- 该路径是当前意图，可以在之后重新规划，不是对未来真实执行轨迹的预知。
- H 尚未定值；建议消息携带生成时刻和有效长度。

必须在模型规范中区分两个标签：某时刻机器人实际持有的计划，以及之后真实执行的位置序列。二者不能混用为同一种“真实计划”。

测试中，邻居未发送的计划不能作为接收方模型输入；可以由评测器保留，离线计算预测误差。训练时额外使用这些标签属于须披露的集中监督。

### 已确认的两条学习路线

| 路线 | 计划模型与策略的关系 | 策略训练数据 |
| --- | --- | --- |
| A：计划预测辅助探索 | 预测邻居目标与短期路径，作为分散策略的可用输入 | 真实仿真环境中的交互轨迹 |
| B：想象轨迹训练 | 在计划预测之外，建模足以推进虚拟交互的动作条件转移、奖励与继续/终止信号 | 世界模型生成的想象轨迹；模型本身仍需真实仿真数据训练 |

两条路线均包含学习式通信主方法和固定通信对照。A 中的多步邻居计划预测不等于 B 中用于策略优化的想象交互。JAX 环境批量执行与世界模型内部想象是两条需分别验证、分别测量的计算路径。

以下为落实两条路线的架构和实验建议，尚待完整设计审阅：

- 共享环境、消息协议、预算规则、地图划分和评测器；尽可能对齐策略接口，披露模型容量与架构差异。
- 分离邻居计划预测模块与环境动态预测模块。前者可供 A、B 复用；B 还需要能闭合想象 rollout 的动态表示和预测头，不假定替换计划解码器就足够。
- B 的想象执行应保持固定编号顺序、航点动作含义、消息可见性及预算约束。已知账本规则可精确推进，不要求全部由神经网络学习。
- 集中训练可以提供额外监督或使用集中式 critic，但分散 actor 的输入仍须由本地历史和收到的消息形成；测试时不能读取全局隐状态或未送达的计划。
- 对齐真实环境交互预算，分别报告模型训练成本、想象转移数量、训练时间与实际通信成本，不把想象样本计作真实交互样本。
- 建议在 A、B 内分别运行“固定/学习式通信 × ZOH/学习式计划预测”对照。ZOH 组仅禁用邻居计划预测对 actor 的供给；B 为推进想象所必需的其他动态预测能力仍需保留并披露，避免把 ZOH 误称为完全无模型。
- 建议实施顺序为共享环境与简单基线、A 训练闭环、B 训练闭环、统一评测；顺序安排不改变两条路线均属于第一版的范围。
- 验收应分别证明 A 能以计划预测辅助真实交互训练，B 的策略确实从想象轨迹获得更新；最终任务性能均在真实仿真环境中的独立测试地图上测量，不以预测误差或想象回报代替。

## 7. 已提出、尚未单独冻结的建议

以下是讨论中的建议，不应未经说明当作用户已逐项确认的最终规则：

- 完成阈值初设为可达自由区域的 99%；具体分母与起点连通性检查需要规范化。
- 记录覆盖阈值达成率、覆盖曲线面积、任务轮次、累计移动距离、通信成本及重复探索指标。
- 实际发射即扣预算，失败也扣；预算不足则拒绝发射；消息头计费。
- 广播按一次发射计费，多个接收者不重复扣发送成本；转发由转发者另行付费。
- 第一版预算不自动补充，预算耗尽后仍允许感知、移动和接收。
- 局部故障同时阻断被隔离机器人的入站与出站消息，不停止运动或感知，不清空历史记忆。
- 故障消息不自动缓存补发；故障日程不作为策略输入。
- 在全队轮次边界触发和解除突发故障，避免边界轮次造成额外编号差异。
- 初始比较包含不使用邻居计划、ZOH 和学习式计划预测；其余消息权限和预算必须一致。

## 8. 编写完整规格前需集中确定的事项

### 环境与消息时序

- 在单机器人回合中，规划、计划生成、移动、感知、发射和接收的精确先后顺序。
- 尚未轮到行动的邻居，其最新计划是上一回合的计划；训练标签必须按事件时间对齐。
- 通信按移动前还是移动后的位置判定；是否采用确认消息，确认消息是否计费。
- 消息容量、每回合发射次数、发送对象、转发机制及缓存上限。
- 航点候选数量、不可达动作处理、路径规划规则和可见性边界规则。

### 学习方法

- 探索学习算法、计划预测模型及二者的训练顺序。
- A 与 B 均已确认为第一版要求；仍需确定具体算法、共享模块范围、B 的动态状态表示及真实/想象训练更新安排。
- 计划预测损失、消息缺失与消息年龄的表示、预测不确定性和多步评测方式。
- 主方法学习发送时机及消息选择已确认；仍需定义通信动作空间、训练目标和固定调度对照规则。
- 训练预算、模型选择规则、重复种子数和计算资源报告方式。

### 参数与评测

- 地图尺寸、分辨率、感知半径、d_max、计划长度 H 和机器人数量档位。
- 训练地图混合比例、生成器类型、验证集及测试集清单。
- 通信预算、丢包率、隔离规模、开始轮次及持续时间的档位。
- BER 的全称与公式尚未给出，暂不把它作为已定义的主指标。
- 编译时间、稳定运行吞吐、峰值内存与包含策略推理的端到端吞吐分别测量；明确一步指单机器人行动还是全队轮次。

这些内容应在下一份完整规格中集中给出建议配置和理由，再进行整体审阅，避免继续逐个数值确认。
